# 织灵：从源代码生成 Windows 安装包

适用版本：2.1.0。本文针对 Windows 10/11 的 64 位电脑。本次实际使用 Node.js 24.12.0、npm 11.6.2 验证。

你只需要准备源代码、安装 Node.js，然后在项目文件夹里运行几条命令。**开发电脑需要 Node.js，拿到安装包的普通使用者不需要安装任何开发环境。Python 也不需要。**

## 1. 准备源代码

这台电脑的项目已经在：

```text
E:\work-space\novel-atlas
```

打开这个文件夹，应能看到 `package.json`、`package-lock.json`、`src`、`electron` 等文件或文件夹。这一层才是项目根目录，不要进入 `src` 后再打包。

在另一台电脑上，可以从 <https://github.com/Symplatt/zhiling> 点击 **Code → Download ZIP**，下载后先解压，再打开含 `package.json` 的那一层。源代码必须包含你想打包的修改；GitHub 上旧版本的源码不会自动包含本机尚未上传的修改。

## 2. 安装 Node.js（只做一次）

从官网 <https://nodejs.org/> 下载 Windows x64 安装程序，使用 Node.js 24 系列即可。安装时保留默认选项和 npm，一路继续到完成。

这台开发电脑已经安装了 Node.js，可以跳过安装。安装后重新打开 PowerShell，再分别输入：

```powershell
node --version
npm.cmd --version
```

能看到版本号就可以继续。若提示“不是内部或外部命令”或“无法识别”，先关闭并重新打开 PowerShell；仍不行，再检查 Node.js 是否安装成功。

下面特意使用 `npm.cmd`，在 PowerShell 中不用修改脚本执行策略。

## 3. 打开项目目录

右键 Windows 开始按钮，打开“终端”或“Windows PowerShell”。复制下面这一行并按回车：

```powershell
cd "E:\work-space\novel-atlas"
```

如果项目在其他目录，就把引号中的路径换成你自己的。然后输入：

```powershell
Get-Item package.json
```

能列出这个文件，说明目录选对了。若提示找不到文件，先改正目录，不要继续执行安装命令。

## 4. 安装项目依赖

第一次在这台电脑上打包，或者更新过 `package-lock.json` 后，运行：

```powershell
npm.cmd ci
```

第一次需要联网，会下载项目依赖，可能要等几分钟。等命令结束、重新出现可输入命令的提示行再继续。出现红色错误并中断时先处理错误，不要当作成功。

只修改了页面、样式或其他源代码，依赖没有变化时，后续可以跳过这一步。

## 5. 检查并生成安装包

先关闭从项目 `release` 文件夹运行的织灵测试窗口。你平时安装的软件也建议先关闭。

运行自动检查：

```powershell
npm.cmd test
```

确认显示测试通过后，再运行：

```powershell
npm.cmd run pack:release
```

这条命令会自动检查 TypeScript、构建页面，并生成 Windows 一键安装包和免安装程序。首次打包可能还要联网下载 Electron 或安装包制作工具，需要多等一会儿。后续已有缓存会快一些。

**等命令正常结束再打开输出文件。** 如果出现报错，或最后显示失败，不要发送看起来已经生成、但可能不完整的 EXE。

## 6. 到哪里拿安装包

打开项目下面的 `release` 文件夹：

```text
E:\work-space\novel-atlas\release
```

2.1.0 版本会生成：

| 文件 | 用途 |
| --- | --- |
| `织灵-安装程序-2.1.0.exe` | 发给普通使用者的安装包，双击安装，并创建桌面快捷方式 |
| `织灵.exe` | 免安装桌面程序，双击即可打开 |
| `win-unpacked` 文件夹 | 打包过程生成的完整程序目录，一般不用分发 |
| `.blockmap` 等其他文件 | 构建辅助文件，手动分发安装包时不需要 |

**推荐给别人发送“织灵-安装程序-2.1.0.exe”和安装使用说明。** 不需要发送 `node_modules`、源代码或整个 `release` 文件夹。

注意：项目根目录也有一个 `织灵.exe`，它是旧的浏览器版启动器。要拿本次打包的桌面版，请认准 `release` 文件夹里的文件。

如果想把安装包复制到 D 盘根目录，可以运行：

```powershell
Copy-Item -LiteralPath ".\release\织灵-安装程序-2.1.0.exe" -Destination "D:\织灵-安装程序-2.1.0.exe"
```

## 7. 下次更新如何修改版本号

当前版本是 2.1.0。下一次要发布 2.1.1 时，在项目目录运行：

```powershell
npm.cmd version 2.1.1 --no-git-tag-version
```

这会同步修改 `package.json` 和 `package-lock.json`。不要只改安装包文件名来冒充新版本。

接着更新安装使用说明里的版本号，再运行：

```powershell
npm.cmd test
npm.cmd run pack:release
```

新文件会叫 `织灵-安装程序-2.1.1.exe`。文中的其他文件名也相应换成新版本。

## 8. 常见问题

**找不到 package.json：** PowerShell 当前目录不对，回到第 3 步。

**下载慢、超时、连接失败：** 检查网络后重试当前命令。不要删除源代码或作品数据，也不用关闭安全防护。

**提示 Can't open output file、EBUSY 或文件被占用：** 先关闭从 `release` 运行的程序及可能占用输出文件的窗口，稍等后重新执行打包。本项目曾遇到第一次打包输出文件短暂被占用、重试成功的情况。

**其他红色报错：** 从第一处报错开始复制文字，或者截图反馈；不要只截最后一行。测试没通过时，先修复再打包。

**别人电脑提示未知发布者：** 当前安装包没有购买代码签名证书，这不表示需要安装 Node.js。请让对方核实文件来源；安全软件明确报告病毒时，应核查原因，不要要求关闭防护。

**打包后会不会把我的小说发出去：** 当前配置只打包程序资源，`data` 下的私人作品不在安装包里。迁移作品请在软件中“备份整个书架”，再到目标电脑导入 JSON。

**运行打包命令会不会自动发到 GitHub：** 本机生成安装包和发布 GitHub Release 是两件事。检查 `release` 中的文件能正常运行后，再根据需要手动上传 GitHub Release 附件。本教程不要求设置 GitHub 令牌。

## 熟悉以后，只记这些

依赖已安装、版本号已确认、当前目录是项目根目录时：

```powershell
npm.cmd test
npm.cmd run pack:release
```

正常结束后，到 `release` 里拿对应版本的安装程序。
